# Лесно разработване на фронтенд за уеб сайт с ESP32, чрез Node.js прокси сървър

При разработване на фронтенда в `ESP32`, се губи ненужно време за записване във флаша на стични html страници след промяна в дизайна им. Целта на този проект е разработване на `Node.js` сървър, който работи със същите html страници и промените да се извършват мълниеносно. Този `Node.js` сървър чрез прокси да се обръща към `RESTful API` бакенд сървър в `ESP32`. По този начин при готов (или полуготов) бакенд, може бързо и без бавене за флаш операции да се разработи фронтенда.  

Идеята е взета от разработката на фронтенда в [restful_server v6.0.1](https://github.com/espressif/esp-idf/tree/v6.0.1/examples/protocols/http_server/restful_server#about-developing-frontend-and-backend-independently) пример на сървър. Там е показан режим на резработка и крайно внедрявне във флаш. За съжаление примера е с `Vue` и `vuetify`, които са твърде тежки и обемни за малък домашен уеб сървър.  

Решението е да разработя сам `Node.js` прокси сървър. Имам опит със направа на сървър с `Node.js`, но съм абсолютно неопитен с прокси часта. Затова ще изпозвам неоценимита помощ на `AI` и ще се преборя с предизвикателството.  

## План за работа

Използване на горепосочения `restful_server v6.0.1` пример като рамка за този проект.  
За съжалние първо се съобразявам с: **ЗАБЕЛЕЖКА** Имам проблеми на етап конфигуриране с `protocol_examples_common` от `idf_component.yml`. Временно решение, прибиране на нужните файлове в директорие: `common_components` в самия проект. Този проблем е заради нещо в ESP-IDF, после ще го търся.  

Изплзва се готовия бакенд `RESTful API` сървър в `ESP32`. Интерисуват ни трите му ресурса с които ще работим:  
GET /api/v1/system/info  
GET /api/v1/temp/raw  
POST /api/v1/light/brightness

Изтриване на старата фронтенд част;  
Вграждане на окончателния (за флаш вариант) фронтенд от [restful_server v5.3.1](https://github.com/espressif/esp-idf/tree/v5.3.1/examples/protocols/http_server/restful_server) в [html_files](/html_files/). Подреждането в поддиректории на този вариант ми е по-приятно;  

- [x] Изграждане на прокси `Node.js` сървър. При получен готов проект от GitHub потреблителя ще трябва само еднократно да:

```bash
cd node_js
npm install
```

При разработка на фронтенда е нужно само пускане на `Node.js` сървъра от главното директори:

```bash
node --watch node_js/my_server.mjs
```

Или:

```bash
cd node_js
npm start
```

След което се свързваме с <http://localhost:3000> и можем да даботим по web дизайна, без да флашваме `ESP32`.  

Но сега за създаване на прокси `Node.js` сървъра, трябва да се изпълнят следните подготвителни подточки:  

1. Създаване на `package.json` файл: в `cmd` `cd node_js` и `npm init`;
2. Инсталиране на необходимите ни `js` модули:  в `cmd` `cd node_js` и `npm install express`;
3. Създаване на обикновен `Node.js` сървъра в [my_server.mjs](/node_js/my_server.mjs);
4. Надграждане на `Node.js` сървъра в прокси;

- [x] Преобразуване на [html_files](/html_files/) от `Vue` и `vuetify` към прозаичен уеб дизайн;

## Заключение

Прекрасен резултат. Много лесно изпълних "[x] Преобразуване на [html_files](/html_files/) от `Vue` и `vuetify` към прозаичен уеб дизайн;", благодарение на новосъздадено прокси. Без прекопилиране и претоварване. Няма нужда от преконфигуриране от развой към флаш както при `restful_server v6.0.1`, Достатъчно е прекомпилиране и записване във флаш накрая.
